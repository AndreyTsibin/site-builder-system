## 1. Executive Summary

**What:** Локальный конструктор лендингов с AI-генерацией контента на основе готовых секций ("LEGO-подход").

**Why:** Tilda не имеет CSS-переменных → невозможно глобально изменять стили на многостраничных сайтах. AI в Tilda примитивная. Нужен инструмент для быстрой сборки качественных лендингов с умной дизайн-системой.

**Who:** Андрей (личный инструмент для заказов на лендинги от клиентов).

**When:** Без жёстких дедлайнов. Постепенная разработка с фокусом на качество. MVP с 5-7 секциями → расширение до 15+ секций → дополнительные фичи.

## 2. Problem Statement

### 2.1 Current Situation

**Основная проблема:**

Конструктор Tilda имеет критические ограничения:
- ❌ **Нет CSS-переменных** → невозможно глобально изменить цвета кнопок, форм, типографику на многостраничных сайтах
- ❌ **Примитивная AI** → не может генерировать качественный контент для секций
- ❌ **Отсутствие гибкости** → сложно кастомизировать секции под конкретный бизнес
- ❌ **Vendor lock-in** → зависимость от платформы, нельзя экспортировать чистый код

**Текущий workflow:**
1. Создаю лендинг в Tilda
2. Вручную заполняю каждую секцию (заголовки, описания, изображения)
3. Копирую контент из одного проекта в другой
4. Если нужно изменить стиль → правлю CSS в каждой секции отдельно
5. **Проблема:** Трачу 3-5 часов на один лендинг, много рутины

**Целевой workflow:**
1. Заполняю `business-data.md` (5-10 минут)
2. Говорю Claude Code: *"Собери лендинг для ремонта стиральных машин"*
3. Claude предлагает секции → утверждаю список
4. Получаю готовый лендинг с контентом за **< 5 минут**
5. Копирую код в Tilda (блок T123) или выгружаю на хостинг

### 2.2 User Persona

**Имя:** Андрей

**Роль:** Веб-разработчик / Фрилансер

**Цели:**
- Быстро создавать качественные лендинги для клиентов (< 5 минут вместо 3-5 часов)
- Иметь полный контроль над дизайн-системой (CSS-переменные)
- Получать AI-генерацию контента высокого качества (через Claude)
- Экспортировать чистый HTML/CSS/JS код (без vendor lock-in)

**Pain Points:**
- Трачу много времени на заполнение одинаковых секций вручную
- Не могу глобально изменить стили в Tilda
- AI в Tilda генерирует слабый контент
- Хочу больше гибкости и автоматизации

## 3. Goals & Success Metrics

### 3.1 Business Goals

**Primary Goal:**
Создать личный инструмент для ускорения работы над заказами лендингов.

**Secondary Goals:**
1. Сократить время сборки лендинга с **3-5 часов до < 5 минут**
2. Создать библиотеку **15+ типов секций** (Header, Hero, Features, Pricing, Footer и т.д.)
3. Разработать **умную дизайн-систему** с CSS-переменными (легко менять цвета, шрифты, spacing)
4. Обеспечить **качественную AI-генерацию** контента через Claude Code

### 3.2 User Goals (Андрей)

1. **Скорость:** Собрать лендинг за < 5 минут (от команды до готовых файлов)
2. **Качество:** Получить красивый, адаптивный лендинг с отличной производительностью (PageSpeed 90+)
3. **Гибкость:** Легко кастомизировать дизайн под любой бизнес (CSS-переменные)
4. **Автоматизация:** Минимум ручной работы (AI заполняет контент, скрипт собирает файлы)

| **Время сборки лендинга** | < 5 минут | Таймер (от команды до готовых файлов) |

**Ключевые преимущества:**

1. 🚀 **Скорость** — < 5 минут от идеи до готового лендинга

## 6. Core Features (MVP Scope)

### 6.1 Must-Have Features (P0)

**Эти функции ОБЯЗАТЕЛЬНЫ для первой версии.**

#### Feature 1: Дизайн-система с CSS-переменными

**Description:** Глобальная система стилей с CSS-переменными для цветов, типографики, spacing.

**User Story:** Как разработчик, я хочу изменить цвета и шрифты в одном файле, чтобы стили применились ко всем секциям.

**Acceptance Criteria:**
- [ ] Файл `design-system.css` с CSS-переменными (цвета, типографика, spacing)
- [ ] Цветовая система на основе HSL (легко переключать светлую/тёмную тему)
- [ ] Типографическая шкала (12px → 48px) на основе Inter font
- [ ] Spacing система (4px base unit, шкала 4px → 240px)
- [ ] Адаптивность (breakpoints: mobile 320px, tablet 768px, desktop 1024px)
- [ ] UI-элементы (border-radius, box-shadow, transitions)

**Референсы:**
- `/dox/The Easy Way to Pick UI Colors/` (цветовая система)
- `/dox/The 80% of UI Design - Typography/` (типографика)
- `/dox/The Easy Way to Design Top Tier Websites/` (общие принципы)

---

#### Feature 2: Библиотека секций (HTML + CSS)

**Description:** Готовые секции (компоненты) для быстрой сборки лендингов.

**User Story:** Как разработчик, я хочу иметь готовые секции (Header, Hero, Features и т.д.), чтобы собирать лендинги как LEGO.

**Acceptance Criteria:**
- [ ] **P0 секции (обязательные, 5-7 шт):**
  - Header (логотип, меню, телефон, кнопка, бургер-меню)
  - Hero-1 (центрированный с формой)
  - Hero-2 (с изображением)
  - Features-2col (преимущества в 2 колонки)
  - Features-3col (преимущества в 3 колонки)
  - CTA (призыв к действию)
  - Footer (логотип, меню, контакты, соцсети)

- [ ] **P1 секции (важные, 8+ шт):**
  - About/Story
  - Pricing (прайс-листы)
  - Contact Form (форма связи)
  - Testimonials (отзывы)
  - FAQ (аккордеон)
  - Stats/Numbers (впечатляющие цифры)
  - Gallery (галерея работ)
  - How it Works (процесс работы)

- [ ] Каждая секция хранится в `/library/sections/{id}/`:
  - `{id}.html` (HTML-разметка с плейсхолдерами `{{hero.title}}`)
  - `{id}.css` (стили секции)

- [ ] Секции адаптивные (mobile-first подход)
- [ ] Иконки через Remix Icon (2800+ иконок, open-source)

---

#### Feature 3: Система плейсхолдеров и AI-генерация контента

**Description:** Плейсхолдеры в HTML (`{{hero.title}}`) + Claude Code заполняет их контентом.

**User Story:** Как разработчик, я хочу чтобы Claude автоматически заполнил заголовки, описания и контент, используя данные клиента.

**Acceptance Criteria:**
- [ ] Плейсхолдеры в HTML:
  - `{{hero.title}}`, `{{hero.subtitle}}` (заголовки)
  - `{{features.item1.title}}`, `{{features.item1.text}}` (преимущества)
  - `{{pricing.service1}}`, `{{pricing.price1}}` (цены)
  - `{{contacts.phone}}`, `{{contacts.email}}`, `{{contacts.address}}` (контакты)
  - `{{testimonials.review1}}`, `{{faq.question1}}` (отзывы, FAQ)

- [ ] Файл `business-data.md` (Markdown) с данными бизнеса:
  - Основная информация (тип бизнеса, название, города)
  - УТП (уникальные торговые предложения)
  - Услуги и цены
  - Контакты (телефон, email, адрес, график работы)
  - Соцсети

- [ ] Claude Code заполняет плейсхолдеры:
  - **Данные есть в `business-data.md`** → вставляет как есть
  - **Данных нет** → генерирует сам (заголовки, описания, отзывы, FAQ)

- [ ] AI-генерация учитывает контекст:
  - Тип бизнеса (услуги, товары)
  - Целевая аудитория
  - Город/география

---

#### Feature 4: Описание секций для Claude (sections-library.yaml)

**Description:** Файл-справочник всех доступных секций в формате YAML для Claude Code.

**User Story:** Как разработчик, я хочу чтобы Claude понимал какие секции доступны и предлагал подходящие для конкретного бизнеса.

**Acceptance Criteria:**
- [ ] Файл `templates/sections-library.yaml` с описанием всех секций:
  - `id` (уникальный идентификатор, например `header-1`)
  - `name` (название секции, например "Header — Логотип + Меню + Телефон")
  - `category` (категория: header, hero, features, pricing и т.д.)
  - `description` (краткое описание функционала)
  - `best_for` (для каких типов бизнесов подходит)

- [ ] Claude Code читает этот файл при команде *"Предложи секции"*
- [ ] Claude анализирует `business-data.md` и предлагает релевантные секции
- [ ] Пользователь утверждает или корректирует список секций

**Пример структуры YAML:**
```yaml
sections:
  - id: "header-1"
    name: "Header — Логотип + Меню + Телефон + Кнопка"
    category: "header"
    description: "Классический header с sticky, бургер-меню"
    best_for: ["Услуги B2C", "Телефонные обращения"]

  - id: "hero-1"
    name: "Hero — Центрированный с формой"
    category: "hero"
    description: "H1, подзаголовок, форма захвата email"
    best_for: ["Лид-магниты", "Подписка"]
```

#### Feature 5: Python-скрипт сборки (assemble.py)

**Description:** Автоматический скрипт для сборки лендинга из выбранных секций.

**User Story:** Как разработчик, я хочу запустить скрипт, который соберёт лендинг из выбранных секций и создаст готовую структуру файлов.

**Acceptance Criteria:**
- [ ] Скрипт `scripts/assemble.py` выполняет:
  1. Читает `selected-sections.json` (список выбранных секций)
  2. Копирует секции из `/library/sections/` в `/output/{project-name}/`
  3. Склеивает HTML секций в `index.html`
  4. Собирает CSS секций в `css/sections.css`
  5. Копирует `design-system.css`
  6. Создаёт структуру:
     ```
     /output/{project-name}/
     ├── index.html
     ├── css/
     │   ├── design-system.css
     │   └── sections.css
     ├── js/
     │   └── main.js
     └── assets/
         └── images/
     ```

- [ ] Файл `selected-sections.json` (JSON):
  ```json
  {
    "project_name": "washing-machine-repair",
    "sections": [
      {"id": "header-1", "order": 1},
      {"id": "hero-2", "order": 2},
      {"id": "features-3col", "order": 3},
      {"id": "pricing", "order": 4},
      {"id": "footer-1", "order": 5}
    ]
  }
  ```

- [ ] Скрипт запускается командой: `python scripts/assemble.py`
- [ ] Скрипт выводит лог: какие секции склеены, время сборки

**Description:** Markdown-шаблон для заполнения данных бизнеса клиента.

**User Story:** Как разработчик, я хочу иметь готовый шаблон для быстрого заполнения данных клиента.

**Acceptance Criteria:**
- [ ] Файл `templates/business-data.md` (Markdown) с разделами:

## 12. Дизайн-система (детали)

### 12.1 Цветовая система (HSL формат)

**Ключевые переменные:**

```css
/* Background (Фон) */
--bg-dark: hsl(0, 0%, 0%);      /* Самый тёмный */
--bg: hsl(0, 0%, 5%);            /* Основной фон */
--bg-light: hsl(0, 0%, 10%);    /* Светлый фон */

/* Text (Текст) */
--text: hsl(0, 0%, 95%);         /* Основной текст */
--text-muted: hsl(0, 0%, 70%);  /* Приглушённый текст */

/* Brand Colors (Брендовые цвета) */
--primary: hsl(220, 90%, 56%);   /* Основной цвет (кнопки, ссылки) */
--secondary: hsl(280, 60%, 60%); /* Вторичный цвет */
--accent: hsl(340, 82%, 52%);    /* Акцентный цвет */

/* Semantic Colors (Семантические) */
--success: hsl(142, 71%, 45%);   /* Успех (зелёный) */
--warning: hsl(38, 92%, 50%);    /* Предупреждение (жёлтый) */
--error: hsl(4, 90%, 58%);       /* Ошибка (красный) */

/* UI Elements */
--border: hsl(0, 0%, 20%);       /* Границы */
--gradient: linear-gradient(...); /* Градиенты */
```

**Принцип:** Вычитание L-value из 100 для переключения тёмной/светлой темы.
