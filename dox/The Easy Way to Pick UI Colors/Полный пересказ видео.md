## Основная концепция

Автор утверждает, что цвета — на самом деле самая простая часть UI-дизайна. Главная хитрость — вовремя остановиться и выбрать то, что работает, вместо бесконечных экспериментов.[^1]

## Три типа цветов для UI

Для дизайна интерфейсов нужны всего три категории цветов:[^1]

1. **Нейтральные цвета** — для фона, текста, границ и большинства элементов
2. **Брендовый/основной цвет** — для главных действий и добавления характера
3. **Семантические цвета** — для передачи разных состояний

## Почему HSL лучше HEX и RGB

Автор объясняет, что большинство знакомы с HEX и RGB, но они худшие для создания цветовых палитр. В HSL формате код имеет смысл:[^1]

- **Hue (оттенок)** — от 0 до 360 на цветовом круге
- **Saturation (насыщенность)** — от 0 до 100, контролирует интенсивность
- **Lightness (светлота)** — используется для создания оттенков

При создании нейтральной палитры saturation ставится на 0, и тогда hue не имеет значения.[^1]

## Создание темного режима

Для фоновых цветов в темном режиме автор использует:[^1]

- **0% lightness** — базовый цвет
- **5%** — для карточек и элементов поверхности
- **10%** — для выделения самых важных элементов

Более светлые элементы кажутся ближе к пользователю, поэтому их используют только для важных вещей.[^1]

Для текста: более резкий и контрастный цвет для заголовков, немного приглушенный для остального. Поэтому для заголовков не используется 100% lightness — это слишком резко для глаз.[^1]

## Переход на светлый режим

Для создания светлого режима автор вычитает значение lightness из 100 — это дает хорошую стартовую точку. Затем вручную корректирует значения:[^1]

- В светлом режиме свет обычно падает сверху, поэтому верхний элемент должен быть самым светлым
- Используются названия типа "BG dark" и "BG light", которые работают в обоих режимах

## CSS-реализация

Автор показывает простую структуру CSS:[^1]

- Дефолтная тема в `:root`
- Другая тема в селекторе `body`
- Одна строка JavaScript для переключения
- Или медиа-запрос для автоматической адаптации к настройкам пользователя

## Улучшение визуала

Для улучшения внешнего вида добавляются четыре свойства:[^1]

1. **Border** — четко видимый, но не отвлекающий
2. **Градиент** — используя фоновые цвета
3. **Highlight** — более светлый цвет для верхней границы (эффект освещения сверху)
4. **Тень** (для светлого режима) — для создания глубины

Для реалистичных теней нужно смешивать более темную короткую тень с более светлой длинной.[^1]

## OKLCH — современный формат

Автор представляет свой инструмент, который позволяет играть с hue и saturation в реальном времени. По умолчанию используется формат OKLCH:[^1]

- **L** — lightness (от 0 до 1)
- **C** — chroma, аналог saturation (от 0 до 0.4, для UI редко нужно больше 0.15-0.2)
- **H** — hue (от 0 до 360)

OKLCH — новая и улучшенная версия LCH. С обновлением V4 Tailwind тоже переключился на OKLCH как формат по умолчанию.[^1]

## Сравнение форматов

Главная проблема HSL — обработка lightness. Темные и светлые оттенки теряют всю насыщенность. С LCH и OKLCH приращения выглядят намного естественнее.[^1]

Автор показывает визуальные сравнения разных форматов и оставляет выбор за зрителем. В финале предлагает готовую тему с обоими форматами (HSL и OKLCH) для темного и светлого режимов — просто копируй и вставляй в CSS.[^1]
